## 它解决什么问题

三个真实场景，你对号入座：

1. **想扒 B 站课程的字幕做笔记**，UP 主没上传字幕，只能边看边暂停手打。
2. **想拿 YouTube 视频的文字稿**做翻译或摘要，官方字幕接口又不好直接调。
3. **手上有个 3 小时的无字幕长视频**（讲座、ASMR、直播回放），市面上的工具要么装 Python + ffmpeg，要么跑一半就崩。

这个脚本把三件事合到一起：**取字幕、没字幕就听写、长视频也扛得住。**

## 核心能力

### 一、三种字幕来源，自动选优

| 来源 | 支持情况 |
|---|---|
| B 站官方字幕 | WBI 签名稳定调用，人工字幕优先于 AI 字幕，中文优先于其他语种，多 P 视频自动跟 P |
| YouTube 字幕 | 解析播放器响应里的字幕轨道，TTML 双形态时间戳全兼容，自动字幕标注 AI |
| 通用网页 | 扫描 `<video>` 下的 `<track kind="subtitles|captions">`，WebVTT / SRT 都能吃 |

### 二、没字幕就 AI 听写（四层防线，v9.0 起首选分段解码）

```
拿到音频地址
   │
   ├─ 有分片目录（B站 dash）─► ① 分段解码（v9.0 首选：逐片下载 + 逐片解码，内存恒定，完全不播放）
   │
   ├─ ≤40MB ────────────────► ② 整段直传（原始文件直接送模型，最快）
   │
   └─ 其余 ──┬──────────────► ③ 解码切片（16kHz 解码，几十秒出结果）
             │
             └──────────────► ④ 静音播放录制（最后兜底，内存恒定）
```

- **① 分段解码（v9.0 首选）**：B 站音频是分片 MP4，开头一小段是「说明书」，紧跟一个「分片目录」，写着每一片的大小与时长。脚本读说明书 → 按目录并发取片 → 每片单独解码 → 攒够 2 分钟送一次识别。**不播放、不整段解码，内存只占当前一片**，跟视频多长无关。
- **② 整段直传**：小文件不解码，原样丢给 SenseVoice。
- **③ 解码切片**：一次性解码成 16kHz 再切片。v8.2 把这一步的内存降了下来（立体声省 2.75 倍、单声道省 5.5 倍）。
- **④ 静音播放录制**：最后兜底。浏览器按倍速静音播放，边播边抓边转，内存恒定。
- **前一路不通自动走下一路**，一条路堵不死。
- **MIME 自愈**：文件头魔数探针（ftyp / RIFF / EBML / OggS / ID3），服务器标错类型也能纠正后重试。
- **选路不再靠猜**：读取音频真实时长与真实声道数再算内存占用，避免把 3 小时当 1 小时处理。

### 三、可选翻译

转写完直接翻。硅基流动 Qwen2.5-72B / 7B / DeepSeek-V3 三选一，批量 120 条一次调用。

### 四、导出（双形态）

- **TXT / SRT / 一键复制**照旧：TXT 带 UTF-8 BOM，Windows 记事本不乱码；SRT 带时间戳，可挂播放器。
- **v9.1 起双形态**：
  - **给 AI 的纯文本**（默认）：剥掉时间戳、去掉相邻重复行、合并成 15–40 字的自然句，直接喂给大模型做摘要/问答。
  - **给人看的章节锚点稿**：只标 3–5 分钟的大锚点，不做逐句——时间戳会漂 ±20 秒，逐句锚点是假精确。

### 五、搜索筛选（v9.1 设计，v9.2 接线）

搜索关键词 → 出候选列表 → 逐条判断「值不值得处理」→ 按总分排 A/B/C 三档。**每条分数都可解释**：加分减分各带 `signal / weight / detail`，为什么加、为什么减，一眼能复核。

**怎么用**

1. 打开面板顶部的「🔍 搜索筛选」Tab，输入关键词（B 站走 wbi 签名搜索免 Key；YouTube 需先在设置里填自备的 Data API Key）。
2. 可选排序（综合/播放/最新/收藏）、「仅有字幕」「最低播放」筛选，点搜索。
3. 脚本对候选**逐条探测原生字幕**（这是权重最高的信号，决定要不要走昂贵 ASR），完成后列表按分数排序。
4. **点卡片第一次**展开完整评分理由；**点第二次**才在新标签页打开视频——先看为什么，再决定点不点。
5. 「⚖ 评分权重」折叠面板里 **11 个滑块直接拖**（松手即保存、当前结果即时换档），下面的 JSON 是高级编辑——两边始终保持同步；JSON 保存前自动校验，清空保存 = 恢复默认。

**评分权重表**（默认值，全部可在设置面板调整——透明是卖点）

| 信号 | 默认权重 | 含义 |
|---|---|---|
| 有原生字幕 | **+42** | 全场最高权重：直接免掉昂贵 ASR |
| 无原生字幕 | **−38** | 全场最高惩罚：只能走 ASR |
| 字幕状态未知 | −8 | 探测失败只轻罚，不误杀优秀候选 |
| 时长 8–60 分钟 | +14 | 知识内容高密度区间 |
| 时长不足 3 分钟 | −18 | 信息密度低 |
| 时长超过 2 小时 | −20 | 处理成本高 |
| 知识类分区 | +16 | 知识/科技/科普/校园/学习/教育/职场/计算机/编程/数码/财经/商业/公开课/讲座 |
| 标题含知识词 | +18 | 教程/讲解/保姆级/从零/入门/原理/拆解/复盘/一文讲透/how to/explained/deep dive/crash course |
| 收藏/点赞比 | 0 / +7 / +14 | ≥0.35 满分、≥0.14 半分；收藏是比点赞更强的干货信号 |
| 投币/点赞比 | 0 / +5 / +10 | ≥0.2 满分、≥0.08 半分；付费式认可 |
| 标题含排除词 | −36 | 直播回放/reaction/挑战/翻唱/整活，重罚 |

**A/B/C 三档的含义**

| 档位 | 分数线 | 建议 |
|---|---|---|
| A | ≥ 55 分 | 优先处理：有字幕或内容扎实，转写花费大概率值 |
| B | 25–54 分 | 看看理由再定：通常差在时长或字幕状态 |
| C | < 25 分 | 跳过：娱乐向、过短或无字幕且无加分项 |

> 已知限制：B 站签名/风控可能失效（`-403` 会自动刷新密钥重试一次，仍失败会明确报错）；判字幕要逐条请求所以慢（20 个候选 = 20 次调用，脚本用 800–1500ms 随机间隔节流降 412 概率）；YouTube 需自备 Key；批量 + ASR 花额度——评分提高命中率，但不改变计费。

### 六、转写质量提升（v9.1 设计，v9.2 接线，三层）

| 层 | 做什么 | 花钱？ | 默认 |
|---|---|---|---|
| 第 1 层 · 热词注入 | 把视频**自己的**标题/简介/标签/UP 主名/分区拆成热词喂给 ASR；账号不支持该参数时**自动去掉重试并关开关**，转写不挂 | 否 | 开 |
| 第 2 层 · LLM 轻量纠错 | 只改错别字/同音字/专有名词，严禁改句式，响应硬校验（条目数/顺序一变整批拒绝） | 是（按调用计费） | **关** |
| 第 3 层 · 标点恢复 + 断句合并 + 相邻重复行去重 | 自动字幕滚动会重复上一句尾巴，先去重再补标点、按 15–40 字合并自然句；幂等标记防重复处理 | 否 | 开 |

- **第 1 层热词为什么来自视频自己的元数据，而不是联网搜索**：ASR 认错的词（人名、产品名、术语）答案几乎必然在视频自己的标题/简介/标签里——UP 主自己写的标题就是最准的上下文，不花钱、不引入搜索噪音，也不用多一次网络请求。
- **第 2 层为什么默认关**：它按调用计费，且「只改错字」的约束需要模型配合；脚本对响应有硬校验（条目数/顺序一变就整体拒绝），但花不花这个钱由你定。
- **第 3 层为什么必须先修再补**：自动字幕滚动显示会重复上一句尾巴，不去重直接补标点会把重复句一起「抛光」成看似正常的废话，所以顺序是先去重、再标点、再断句。

Edge / Chrome / Firefox 应用商店搜「Tampermonkey」一键安装。

**第 2 步 · 拿一个硅基流动 API Key**（只用官方字幕的话可跳过）

用 GitHub 账号登录 [cloud.siliconflow.cn](https://cloud.siliconflow.cn/i/axOmWfWi) 注册，新用户送 ¥16 代金券，跑 AI 转写完全够用。进控制台复制 `sk-` 开头的 Key。

**第 3 步 · 装脚本**

打开 `bili-subtitle.user.js`，把全文粘贴进 Tampermonkey 的「新建脚本」编辑框，保存。

**第 4 步 · 用**

打开任意带视频的网页，右下角出现 🎬 按钮 → 点开 → 点「⚡ 获取字幕」。

纯文字页面不会出现按钮，不打扰。

## 长视频专项（3 小时为什么不崩）

这是 v8.2.0 的主要工作，也是这个项目最能打的地方。

**旧版的三重退化**（60 分钟能用、3 小时不行的真相）：

1. 音频超过 40MB 就被推去「播放录制」，3 小时要真放 13 分钟。
2. 播放位置卡顿 5 秒就判「放完了」，直接截断，还不报错。
3. 界面每 0.8 秒重画全部字幕，主线程被拖住，抓音回调跟着丢帧，时间戳越漂越远。

**v8.2.0 的解法**：

| 手段 | 效果 |
|---|---|
| 解码目标 44100 → 16000 | 3 小时立体声从约 3.8GB 降到约 1.32GB，单声道降到约 659MB |
| 读音频真实时长再选路 | 不再拿文件体积猜码率，避免把 3 小时当 1 小时 |
| 读 MP4 容器里的真实声道数 | 估算不再少算一半；单声道长音频走解码快路，立体声超阈值走稳路 |
| 解码完成后按实际声道复核 | 估算与真实不符时记录提示，不静默冒 OOM 风险 |
| 抓音从 ScriptProcessor 换 AudioWorklet | 音频独立线程，页面卡顿也不丢采样点 |
| 停滞判定看缓冲状态 | 位置与缓冲同时停 20 秒才收尾，不再误杀 |
| 背压闸门 | 待转写切片积压就暂停播放，内存不涨 |
| 转写全程静音 | 播放推进、数据照抓，扬声器一声不出 |

**真机验收步骤**（沙箱跑不了，你的机器 5 分钟能验完）：

1. 找一个 3 小时左右的无字幕视频（例如 `BV1424U6JEGL`，3 小时 33 分）。
2. 点 🎬 → ⚡ 获取字幕 → 看到「本视频无字幕」→ 点 🎙 AI 转写。
3. 观察进度条：下载 → 读时长 → **解码**（通常几十秒）→ 转写（分片走）→ 合并。
4. 验收标准：转写期间**没有声音**；界面实时长出字幕；时间戳与音频对得上；导出 TXT / SRT 中文不乱码。

## 进度与交互

转写过程不再是黑箱：

```
① 下载    ② 读时长   ③ 解码/录制   ④ 转写    ⑤ 合并
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
音频 86MB · 时长 3:33:00 · 已处理 1:12:30 / 3:33:00 · 已用 2:14 · 预计还需 4:06
[00:00:03] 你好，欢迎来到本期节目
[00:00:08] 上一节我们讲到了电子排布
[00:00:15] 现在来看第二主族
```

- **五阶段进度条**：走过的打勾，当前的加亮，总进度按权重折算成一条。
- **实时字幕流**：最近 40 句边转边显示，看得见内容在长。
- **预计剩余时间**：按实测速度外推，随进度自动修正。
- **胶囊小条**：面板收起后显示「🎧 62% · 约 8 分钟」，不挡视频。
- **完成通知**：转完发系统通知，中途可以最小化页面去干别的。
- **可取消**：随时中断，已转好的部分照样保留。

## 常见问题

**Q：提示「未配置硅基流动 API Key」？**
打开 ⚙ 设置，粘贴 `sk-` 开头的 Key 保存。只用官方字幕不需要 Key。

**Q：转写要多久？**
取决于走哪条路。分段解码路（v9.0 首选）音频处理本身只占几十秒，总耗时基本等于识别服务的时间；解码切片路几十秒到几分钟；播放录制兜底路按「音频时长 ÷ 倍速」算。

**Q：转写时会有声音吗？**
不会。v8.2.0 起播放全程静音（增益 0），只让播放位置推进。

**Q：能关掉页面吗？**
最小化或切到别的标签页没问题。完全关闭标签页会中断。

**Q：YouTube 无字幕为什么不能转写？**
YouTube 音频是带签名分片的流媒体，需要解流签名才能取到。脚本会提示改用官方自动字幕，自动字幕本身已支持。

**Q：MSE / `blob:` 视频呢？**
这是浏览器的媒体源扩展保护，页面里没有可直接下载的音频地址，无法取音。

**Q：B 站要登录吗？**
取 AI 字幕通常需要登录 B 站账号（浏览器已有登录态即可）。人工字幕一般不需要。

**Q：搜索 Tab 的 YouTube 搜索为什么要我自己填 Key？**
Google 的策略要求调用方自备 Data API Key，脚本不内置任何 Key。填在 ⚙ 设置里即可，只存本地；B 站搜索不需要 Key。

**Q：搜索出来的视频，怎么判断值不值得转？**
看评分：A 档（≥55 分）优先转，C 档（<25 分）跳过。每条分数都能展开看理由——有没有原生字幕占最大权重，因为它直接决定要不要花 ASR 的钱。

**Q：数据安全吗？**
脚本纯前端运行，无任何后端服务器。设置与 API Key 只存在浏览器本地，不会上传第三方。音频只在你调用转写时发送给硅基流动。
